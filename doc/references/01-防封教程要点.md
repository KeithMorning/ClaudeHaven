## 核心论点

**三条封号红线**：不支持地区（大陆/港澳）、蒸馏/高并发/把个人订阅反代进中转池、违规内容。
作者澄清：官方不是禁止中国人 —— 有读者拿中国护照过 KYC 照样过 —— 防的是「人在不支持地区」
+「批量滥用的机器行为」。判断尺只有一句：**一个在美国工作生活的中国人，会这么做吗？**

**两个决定生死的权重**：注册出生那几天的初始权重干不干净；日常网络有没有偷漏国内 IP。

## 对本项目最重要的三点

### 1. 第三章几乎就是本项目网络防漏的需求文档

它列的「开着代理还漏国内 IP」三个原因 —— 遥测域名不在规则里、没开 TUN 或闪断回落 DIRECT、
让登录中的 Claude Code 自己改 Clash 配置 —— 和本项目一直在修的是同一件事。
它的 11 项验收比 `exit-check.sh` 更严，可直接补进自检：

- 用 `curl --noproxy '*'` 测（否则测的是代理端口而非虚拟网卡）
- 必须**普通用户身份**测（root 不受断网开关限制）
- DoH 随机子域名查代理日志验证 DNS 出口
- 三个断网演练（节点死 / TUN 关 / 客户端退 3 秒后必须全拒）

> 「让登录中的 Claude Code 改网络配置」是作者强调的真实踩坑（评论区 15-16 人栽在这），
> 和本项目「一键重置必须先停会话再销毁」（坑 21）是同一条铁律。

### 2. 它把「不用做 TUN」的判断顶回来一部分

作者把 TUN + 断网防火墙视为防漏必要条件，我们曾用 netlink 删默认路由（效果等价、实现不同）。
1.0.37 落地[内置 TUN](../network/02-TUN与Mihomo.md)后，这条差距已补上。

### 3. 威胁模型反向印证收敛

全文从头到尾是「防平台被动风控」，没有任何「防内部恶意进程」需求 —— 与本项目
[最小充分集的判断](../decisions/04-平台与范围取舍.md)一致。权限审计那套确实不用做，
但防闪断的 TUN / 防火墙值得做（已做）。

## 节点分析实例

`38.150.32.117`：四源交叉（ipinfo / ip-api / ipwho.is / ipapi.co）确认
美国洛杉矶、AS174 Cogent、机房 IP、Scamalytics 11/100 低风险、主流黑名单零命中；
组织归属有转租痕迹（ARIN 显示 Cogent，ip-api/Scamalytics 标 NetLab）。
结论：底子干净的美国机房 IP，可用，但按文章逻辑要先测出口一致性（
`api.ipify.org` / `ipinfo.io` / `claude.ai` / `statsig.anthropic.com` / `googletagmanager.com`
显示的 IP 是否都是同一个）。
