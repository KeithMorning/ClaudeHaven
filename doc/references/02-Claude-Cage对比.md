# 外部参考：Claude Cage 对比

> **来源**：<https://github.com/Lee-xeo/Claude-Cage>（v0.1.8、MIT、Go 重写、三平台、556 次提交）。
> 通过 README、SECURITY.md、docs/getting-started.md、docs/guide/network.md 研读。
> 这是同赛道更成熟的方案，本页记录架构差异与可迁移点，是外部调研不是本项目实现。

## 一句话结论

它和本项目撞在同一条赛道，但**网络层成熟一个量级**；而我们有一件它没有的东西 —— **完整桌面 + 可用中文输入法**。

## 架构差异：强制点在哪

| | ClaudeVM（1.0.36 及之前） | Claude Cage |
| --- | --- | --- |
| 强制点 | 客机内 root 删默认路由（锁和钥匙同房间） | 主机侧虚拟网卡出口，客机 sudo 够不到 |
| 放行模型 | 状态常驻 `guarded` | ≤90 秒租约，24 小时完整报告上限，控制服务失联即到期关闭 |
| 证据处理 | 探测失败当异常 | **证据缺失即断网** |
| 代理 | 借用宿主 Clash 端口 | 包内自带 Mihomo，含链式代理 / 订阅 |
| 断网粒度 | 整条链路死掉 | 只断业务外网，终端/共享文件照常 |
| 平台 | Windows（Mac 容器未实测） | macOS / Windows / Linux 真 VM |
| 桌面 | 完整 openbox 桌面 | **没有完整桌面**，只有浏览器+编辑器页 |
| 中文输入 | fcitx5 + Rime 万象 | 不涉及（绕开了这个问题） |

## 它解决的正是我们上次发现的盲点

不是加检测，而是**从结构上让假绿不可能**：

- 放行是**租约**不是状态 —— 没有「一直 green」可停留
- **证据缺失等于断网** —— 我们把探测失败当异常，它把「没拿到证据」本身当失败
- 自带代理核心 —— 宿主 Clash 什么模式都与它无关，这才是根治
- 强制点在虚拟机外 —— 客机 root 拆不了锁

## 它没有的，恰好是我们的家当

README 明确写「没有完整桌面」。它绕开了中文输入法 —— 我们花 1.0.28~1.0.36 八个版本硬啃的东西。

## 迁移到本项目的判断

曾经列出三条路：① 搬三件（租约 / 证据完整性 / 只断外网）进现有架构；
② 网络层直接用它的、我们做桌面；③ 转用 Cage、本项目收尾。

**最终判断（见[平台与范围取舍](../decisions/04-平台与范围取舍.md)）**：

- 1.0.37 的**内置 Mihomo + TUN**已把「自带代理核心」「结构性 fail-closed」两件落地，
  宿主软件彻底退出运行时链路 —— 相当于用更轻的方式拿到了上述前两条的核心收益。
- **租约制没采纳**：目标只是编码环境，状态常驻 + 结构性断网够用；多账号调度那套用不上。
- **权限审计 / 主机侧强制没采纳**：防的是配置漂移不是内部提权，见威胁模型收敛。
- **不转用 Cage**：它没有完整桌面和中文输入法，那正是本项目的存在意义。

## 体积对照（修正一个印象）

Cage v0.1.8 的 `Cage-0.1.8-macos-arm64.dmg` 只有 **207 MB**，大件在首次启动下载的客机镜像。
OrbStack arm64 DMG 448 MiB + 我们 620 MB rootfs ≈ 1.07 GB。
所以「Cage 太大、我们省体积」并不成立 —— 我们的优势是「下完就能用 + 完整桌面和输入法」。
