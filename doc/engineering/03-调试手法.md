## 容器内自查（不必开应用）

```bash
# 必须 MSYS_NO_PATHCONV=1，否则 Git Bash 会把 /opt/... 改写成 Windows 路径
MSYS_NO_PATHCONV=1 wsl.exe -d claude-vm -u root -- /opt/scripts/check-env.sh --json
MSYS_NO_PATHCONV=1 wsl.exe -d claude-vm -u root -- bash -c 'echo $DISPLAY; cat /run/claude-vm/ready'
MSYS_NO_PATHCONV=1 wsl.exe -d claude-vm -u root -- bash -c 'DISPLAY=:0 xrandr | head -2'   # wslg
MSYS_NO_PATHCONV=1 wsl.exe -d claude-vm -u root -- bash -c 'DISPLAY=:1 xrandr | head -2'   # desktop
MSYS_NO_PATHCONV=1 wsl.exe -d claude-vm -u root -- cat /proc/net/route   # 有 00000000 行 = 默认路由在
MSYS_NO_PATHCONV=1 wsl.exe -d claude-vm -u root -- python3 /opt/scripts/net-guard.py status
```

WSLg 相关：`build/wslg-window.sh`（起窗口）、`build/wslg-term.sh`（终端）、`build/wslg-probe.sh`（探测）。

## 诊断命令的可靠性铁律

**嵌套引号会吞变量，日志会骗人。** 反复踩过的坑：

- `wsl.exe -d ... -- bash -c '...$P...'` 里嵌套引号吞掉变量 → curl 静默不走代理 → 误判「代理挂了」。
- 多行 `bash -c` 经 wsl.exe 传参，换行被吞、变量赋值失效，还照样打印成功标记。
- 快速判定：诊断逻辑一律**写进脚本文件再执行**，不要在命令行里拼嵌套引号。

会话类验证同理：短命 wsl.exe + setsid 会被 WSL 回收整棵进程树，必须用常驻 wsl.exe 后台任务
当宿主（产品 spawn 同款形态）。详见[坑 8/17](../pitfalls/02-网络与代理.md)、
[pitfalls/03-输入法.md](../pitfalls/03-输入法.md)。
