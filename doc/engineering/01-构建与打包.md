# 构建与打包

## 打包命令

```bash
cd claude-desktop
npm config set registry https://registry.npmmirror.com
set ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/
set ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/
npm install

npm start             # 开发运行（会先自动 sync-scripts）
npm run dist:win      # 只出 NSIS 安装包（约 740 MB）
npm run dist:mac      # macOS（必须在 Mac 上跑）
npm run dist:portable # 需要便携版时才跑
```

产物：`claude-desktop/dist/ClaudeVM-Setup-<version>-x64.exe`。macOS 未签名 dmg 首次打开需右键→「打开」。

**构建前先移走旧的 `dist/win-unpacked/`** —— electron-builder 的 safe-delete 会被旧目录卡住
（`dist/win-unpacked-old-<时间戳>` 即可）。

## 脚本同步链（只有一个真源）

```
真源 claude-vm/vm/scripts/
  → sync-scripts.js 生成 claude-desktop/runtime/scripts/（打包副本）
  → 已安装应用 resources/scripts/
  → VM 的 /opt/scripts/
```

改运行时脚本必须走完整条链，并在 VM 内直接执行一次让配置生效。少任何一层都会回到
「修复在包里、不在环境里」（坑 13）。`cp -f` 覆盖运行中的脚本会截断 UTF-8 导致 code=127（坑 2）。
详见[目录地图与 IPC](../overview/02-目录地图与IPC.md)与[坑档案 01](../pitfalls/01-脚本同步与假活.md)。

## rootfs 重建

### 标准方式（有 Docker）

```bash
wsl -d Ubuntu-22.04 -u root -e bash -lc \
  "bash /mnt/<盘符>/<路径>/claude-desktop/scripts/build-rootfs.sh"
```

### 无 Docker 的增量方案（1.0.37 实测）

本机 Windows 与 WSL 都没有 `docker` CLI，`docker build` 走不通时用
`build/rebuild-rootfs-137.sh`：在 WSL ext4 上解压当前 rootfs → 只注入
mihomo 内核（60 MB）+ `geoip.metadb`（4.8 MB）+ 新脚本 → `gzip -1` 重打包。
**好处**：桌面/输入法/字体/Chrome 一个字不动，零回归风险。

配套脚本（可复用）：`check-rootfs-137.sh`（校验）、`finalize-rootfs-137.sh`（校验+原子替换）、
`verify-rootfs-137.sh` / `verify137-detail.sh`（临时发行版真导入验证）、
`verify-setup-137.sh`（安装包内容核验）。

### 重打包踩过的坑（都修进脚本了）

1. `tar tzf | grep -q`：grep 提前退出 → tar 收 SIGPIPE 返回非 0，在 `set -e` 下被误判成
   「新包缺少文件」。先把整表读进变量再比对，别用管道接 `grep -q`。
2. WSL 会把 `localhost proxy configuration was detected ...` 警告混进 **stdout**，
   精确匹配被干扰 → `tar tzf ... 2>/dev/null`。
3. 最终解法：用 bash `case "$NL$ENTRIES$NL" in *"$NL$k$NL"*)` 做整串精确行匹配，
   不启子进程、不建管道，避开 SIGPIPE / pipefail。
4. `wsl --import` 必须在 Windows 侧用 Windows 路径调用，不能在 WSL 里反调 wsl.exe。
5. WSL 命令行里嵌套引号反复吞 `$N`，诊断逻辑一律写进脚本文件再执行。

1.0.37 验证过的临时发行版 `claude-vm-verify137` 已 unregister，旧包备份在
`build/rootfs-pre-137-backup.tar.gz`（建议保留兜底）。

## 版本对齐流程

改完功能后按顺序：① 更新 `claude-desktop/package.json` 的 version →
② 更新 `开发交接.md` 头部的版本/打包时间（文档拆分后以 `doc/` 为准）→
③ `RUNTIME_REV` +1（改了运行时脚本/资源）→ ④ 提交 → ⑤ 重建 rootfs（若镜像内容变了）→
⑥ 构建安装包 → ⑦ `verify-setup-*.sh` 核验 → ⑧ 跑全量测试。

## 源码包

```bash
python build/pack-dev-src.py     # 产出 _pack/claude-vm-dev-src-<版本>-<日期>.zip
```

白名单在 `build/pack-dev-src.py` 的 `TOP_FILES` / `TOP_DIRS`。万象词库 `.zip` 是
有意随源码交付的二进制例外（`SKIP_EXT` 默认排除 zip，但对 `claude-vm/vm/assets/rime/` 开例外）。
已把 `doc/` 纳入白名单，保证换机开发时拿得到这套文档。
