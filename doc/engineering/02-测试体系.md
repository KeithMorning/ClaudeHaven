# 测试体系（1.0.30 起入仓库）

> 文档与「坑→测试」映射表见 `tests/README.md`。发版 checklist 在其文末。

## 三层结构

### 1. `tests/unit/` — 纯函数单测

从 `app/main.js` 按起止标记切片注入 mock（`tests/loader.js`），不需要 WSL，<1 秒。
覆盖：坑 3（代理尾斜杠）/ 坑 13（假活、`RUNTIME_REV` 指纹）/ 坑 15
（`/proc/net/route` 解析、`resolveUpstream` 熔断态仍成功）/ 坑 22（`tun-config` 7 例）。

`tests/unit/backend.test.js` 直接 require `app/lib/vm-backend.js`（不走 loader 切片 —— 这是
「纯函数抽到 lib/ 后直接 require」的重构方向）；断言两个后端接口齐全，含 `destroyAll`。

### 2. `tests/static/` — 静态一致性

- 镜像与打包副本逐字节比对（坑 13）
- `bash -n` / python ast 语法检查
- 关键行为断言：坑 12 的 Close context、坑 14 的 `sleep infinity` / 输入法段位置 /
  SingletonLock、坑 15 的 `stopRuntime` 里 unlock 必须先于 kill、
  坑 21 的「先停后销毁」时序 + 界面二次确认、坑 22 的 TUN 六项接线。

### 3. `tests/integration/` — WSL 集成

net-guard lock→unlock 路由往返实测；**只在环境空闲（ready 为空）时执行**，finally 兜底还原，
绝不碰运行中会话的熔断。

## 跑法

```bash
node --test "tests/**/*.test.js"                                  # 全部（含 WSL 集成；Windows glob 必须带引号）
node --test "tests/unit/*.test.js" "tests/static/*.test.js"       # 快速层（无副作用）
# 或
cd claude-desktop && npm test              # 全量
                        npm run test:fast  # 快速层
```

最新规模：**113/113 全量通过**（1.0.37，含坑 21/22 新增断言）。

## 发版必测

「停止 → 立即启动」是坑 15 的完整场景，每次发版必测。其余见 `tests/README.md` 文末 checklist。

## 为什么要有测试套件

项目已有 22 个约束、八个版本大半耗在输入法与环境边角上。测试把这些「踩过的坑」固化成断言，
避免后续优化或重写时重新裸跑、重复踩同一类问题。详见
[平台与范围取舍](../decisions/04-平台与范围取舍.md)里对「最小充分集」的判断。
