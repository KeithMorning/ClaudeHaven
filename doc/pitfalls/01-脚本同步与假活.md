# 坑档案：脚本同步与假活（坑 1 / 2 / 13）

> [构建与打包](../engineering/01-构建与打包.md)。返回[速查表](index.md)。

## 1) 脚本只有一个真源：`claude-vm/vm/scripts/`。

`claude-desktop/runtime/scripts/` 是自动生成的副本。改副本 = 改了会被覆盖；两边分叉 = 虚拟机里跑的还是旧逻辑。

## 2) 绝对不要用 `cp -f` 覆盖正在运行的脚本。

`cp -f` 是就地截断，正在被 bash 逐行读取的脚本会读到半个 UTF-8 字符并 `code=127` 退出，
表现为「虚拟机自己意外关机」。必须 `cp 到 .tmp && mv`（同分区 rename 是原子的）。
`syncScripts()` 已经是这样实现的，别改回去。

## 13) 1.0.28：「装了新版却不生效」—— 假活判定 + 幂等跳过同步。

- 症状：1.0.27 的 openbox 修复在安装包里（7335B、含 `Close`），但 VM 里生效的
  `~/.config/openbox/rc.xml` 还是 4076B 旧版，✕ 依旧点不动。
- 根因两层：
  1. `runtimeAlive()` 的 desktop 分支 `if (ready === 'desktop') return true` ——
     `/run` 是 tmpfs，Xtigervnc / openbox / websockify 全退出后标记仍在，于是「接管尸体」；
  2. `startRuntime()` 的幂等 `return` 在 `syncScripts()` **之前**，接管时不同步任何脚本/资源；
     旧版 entrypoint 固定 `cp /opt/config/openbox-rc.xml`，把新配置又盖回旧版。
- 修法：① 三个常驻进程 + `waitPort(6080)` 都通过才算活着；② 接管分支也
  `await syncScripts()`；③ `syncScripts()` 把 `/opt/assets/config/openbox-rc.xml` 同时写到
  `~/.config/openbox/rc.xml` **和** `/opt/config/openbox-rc.xml`（旧版回退源），
  再 `DISPLAY=:1 openbox --reconfigure` 热生效；④ `cfgFingerprint` 加 `RUNTIME_REV`，
  改脚本/资源就 +1，升级后强制重建一次。
- 教训：**「修复在包里」≠「修复在运行的环境里」**。`wsl --import` 出来的是持久发行版，
  必须逐段追问「这条链上哪一步会把旧文件写回去」。诊断时直接比三处文件的字节数 +
  `grep -c 'context name="Close"'`，比读代码快得多。
- 同步命令仍用 `'; '` 拼接，新增的 `openboxHotfix` 元素**末尾不能带分号**（否则 `;;`），
  改完用 `bash -n` 验一遍拼接结果（坑 8）。
