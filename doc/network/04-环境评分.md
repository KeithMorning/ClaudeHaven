# 环境评分现状（checkcc 口径 41 分）

> 自检 20 通过 / 3 注意 / 0 失败（1.0.26 起，含环境身份一项）。
> 应用内「运行环境自检」面板可复算这个分数。

## 41% 的构成

| 分 | 项 | 能不能改 |
| --- | --- | --- |
| 13 | 网络出口类型（机房 IP，ASN 判） | 只能换住宅 / ISP 节点 |
| 15 | 多源 IP 情报一致性 | 对方 bug：它查情报源时没带客户端 IP，拿了自己 CF Worker 出口 |
| 5 + 2 | DNS 两项 | 由上面那条派生，不是真 DNS 检测 |
| 6 | claude.ai 可达性 | CF 挑战页的 `CORP: same-origin` 挡掉跨域探活 |

**归因为「本地配置错误」的是 0 分**。换节点（Vultr → NTT）实测分数分毫未动。
详见 `docs/` 与会话记录。

## 为什么网络熔断不会降这个分

1.0.22 的 fail-closed 分数全部来自出口 IP / ASN / DNS / CF CORP，是**代理节点本身的属性**。
熔断解决的是另一种风险 —— 代理意外断开时流量回落到本机直连、把真实环境暴露出去；
这种情况检测站测不到，但后果比多几分严重得多。

## 为什么 1.0.25 的修法也不降分

修的是「浏览器请求头与系统地区打架」「企业 DNS 后缀混进日志」
「自检给出虚假安心和错误建议」这类本地一致性问题。其中「出口类型」现在如实标 warn —— 
AS2914 这类骨干 ASN 在检测站就是 +13 分，属于商业 VPN 节点的固有属性，不是配置错误；
自检旧版给它 pass 反而误导。
