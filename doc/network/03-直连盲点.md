# 已知盲点：代理软件运行中切成直连

> 状态：**1.0.35 发现，用户确认暂不改产品代码**。1.0.37 的 TUN 模式从架构上绕开了它
> （内核自带、宿主软件不进运行时链路），但旧链路（默认）仍存在此盲点。

## 现象

容器侧路由熔断只能保证「流量一定送到宿主代理端口」，管不到代理软件拿到请求后怎么发出去。

- **启动时**：预检会读出口 IP / 地区 / 三源一致性，所以启动时就是直连会被
  `exit-region-risk` 挡住。
- **运行中**：看门狗（`net-guard.sh:284-299`）每 3 秒只探
  `http://cp.cloudflare.com/generate_204` 的 HTTP 码 —— 这个端点国内直连也返回 204，
  且代码只有在预检未通过或状态非 guarded 时才重跑完整预检。于是运行中把 Clash Verge /
  mihomo 切到 Direct 后，界面继续显示旧的境外出口（**静默假绿**），真实流量已从宿主机直连出站。
- `direct_leak=no` 只验证容器能否直连，测不到宿主机代理软件的行为。

## 实测对照（2026-11-09）

- VM 经代理出口 `192.220.30.145 · US · Los Angeles`（ipify / ipinfo / ip.sb 三源一致）
- 宿主机直连出口 `117.133.43.138 · CN · 北京移动`
- 宿主机处于直连并不影响 VM —— 容器显式走 7897 且路由锁死，VM 没跟着直连
- 当时 `net:status` 绿色是真实的，不是陈旧数据；**盲点在于运行中切换的那一刻之后**

## 临时缓解

- 代理软件锁 Global，给 `anthropic.com` 写死走节点
- 随时跑一键自检 `build/exit-check.sh`：同时打印真实出口与界面状态并给判定，
  可传入宿主机直连 IP 做基线比对，直接判定「出口 == 本机直连 IP = 已切 Direct」

```bash
MSYS_NO_PATHCONV=1 wsl.exe -d claude-vm -u root -- bash /mnt/e/Web/FuckCladue/build/exit-check.sh
MSYS_NO_PATHCONV=1 wsl.exe -d claude-vm -u root -- bash /mnt/e/Web/FuckCladue/build/exit-check.sh 117.133.43.138
```

## 未采用的根治方案（供后续优化）

用 `https://www.cloudflare.com/cdn-cgi/trace` 的 `ip=` 字段做周期性出口指纹校验
（无速率限制、直连/代理都可访问），加上 Electron 主进程预先采集的宿主机直连 IP 基线；
命中即写 `blocked/direct-mode-detected`，并用占位地址重新熔断成全断网，代理恢复后自动重跑预检。
更彻底的做法是把这套逻辑并入[内置 TUN](02-TUN与Mihomo.md)，让宿主软件彻底退出运行时链路。

## 关系
