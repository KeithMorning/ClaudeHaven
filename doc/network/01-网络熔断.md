# 网络熔断（net-guard）

> 核心语义：fail-closed。代理是**唯一出口**；代理断开或预检不过时，网络在内核层面直接不通，
> 绝不回落到本机直连。1.0.37 起这条链路由「netlink 删路由」升级为「容器内置内核 + TUN」，
> 但 net-guard 仍是 fail-closed 底座，一行没改。

## 为什么不用应用层的 HTTP_PROXY

`HTTP_PROXY` 只是**建议**：不读环境变量的程序、DNS、raw socket 都能绕过去直连。
真正的约束必须落在内核网络层。

## 实现：直接改内核路由表

精简 rootfs **没有 iptables / nft / iproute2**（连 `ip`、`route` 都没有），但
`CapEff=000001ffffffffff` 含 `CAP_NET_ADMIN`，Python3 有 `AF_NETLINK` —— 所以
`net-guard.py` 直接发 `RTM_DELROUTE` / `RTM_NEWROUTE` 改路由表，**不要为这个去重打 720 MB 镜像装 iptables**。

分工：
- `net-guard.py` — netlink 路由增删的原子操作（lock / unlock / status），零外部依赖
- `net-guard.sh` — 严格预检 + 3 秒看门狗，状态写 `/run/claude-vm/net-guard.state`

## 不能改的几条规则（都是踩过的坑）

1. WSL 路由是 `default via <网关>` + `<网关网段>/20 dev eth0 scope link`。删掉 default 后
   on-link 那条还在，宿主代理仍可达；其余目标 `ENETUNREACH`。代理是公网 IP 时才补 `/32`。
2. **IPv6 必须一起关**（sysctl + 删 v6 默认路由）：只封 v4 是最常见的泄漏口。
3. **顺序**：先 `lock`（毫秒级）→ 再预检 → 再验证「直连确实出不去」。反过来会在预检那几秒
   留下业务流量直连的窗口。
4. 预检不过**不解锁**，保持封锁并写明 reason；`net:status` / 自检都读状态文件。
5. 守卫退出时**不要 unlock**（fail-closed 语义）；恢复只在显式 `NET_GUARD=off` 或重启发行版。
6. 看门狗间隔 3 秒只为兜住「WSL 网络重置把默认路由加回来」；正常代理断开不依赖它。

历史坑（返回值重复键、多行 bash 传参被吞）见[坑 8](../pitfalls/02-网络与代理.md)。

## 「停止→启动」曾必现连不到代理

根因链：`net-guard.py lock` 删默认路由 → `wsl --terminate` **不重建 WSL2 网络命名空间**，
删除的路由残留 → 靠默认路由算宿主地址返回 null → 不 spawn → 死锁。
**只有 `wsl --shutdown` 才恢复默认路由**。修法是多来源候选真实 TCP 探测 + 停止前 unlock。
完整复盘见[坑 15](../pitfalls/02-网络与代理.md)。

## TUN 模式下的 net-guard

1.0.37 起 net-guard 多了一条 `TUN_MODE` 分支：内核 mihomo 的 TUN（table 2022 覆盖路由）
接管全部流量，net-guard 仍删 main 表默认路由作底座 —— 内核一挂，TUN 与策略路由一起消失，
main 表又没默认路由，于是**立刻全断，不需要任何检测动作**。

TUN 分支的三条硬约束（裸 curl、tun-ready、内核存活检查）见
[TUN 与 Mihomo](02-TUN与Mihomo.md)。
