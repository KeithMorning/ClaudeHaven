# 一键环境重置

> 1.0.37 落地（坑 21）。封号后一键销毁旧环境、生成与旧环境零关联的新环境。
> 界面「一键重置环境」按钮是**两段式确认**（第一次只改文案，10 秒内再点才执行）。

## 为什么必须「先停会话，再销毁磁盘」

`stopRuntime()` 只是 `wsl --terminate` / `docker stop`，**数据全留着**，换不掉身份。
顺序反了：运行中的 Claude Code 退出时会把内存里的旧登录态写回 `~/.claude` /
`~/.claude.json`，先销毁磁盘再停进程等于白清（外部参考 PDF 第七章的铁律）。

## 主进程 `runtime:reset` 的执行顺序

1. **`stopRuntime()`** — 先 kill 会话、terminate 实例。**顺序不可反**。
2. **`backend.destroyAll()`** — 彻底销毁：
   - WSL：`wsl --unregister` 删掉发行版 + 清 ext4.vhdx 残留（否则下次 `--import` 报目录非空）；
     未注册不算失败（重置目标就是「最终不存在」）。
   - 容器：`docker rm -f` + `docker volume rm -f claudevm-home` 删掉 `/root` 命名卷。
   - 注意 `stopAll()` 的 `--terminate` / `docker stop` **只停机保数据，不能用于重置**。
3. **清宿主 `last-start.json` 就绪指纹** — 避免下次启动误判「环境还活着」而跳过重建。
4. **立即 `startRuntime()`** — 从 `rootfs.tar.gz` 重新导入，重新生成
   `/opt/config/identity`（hostname / machine-id）、Chrome profile、登录态。

## 保留不改

干净的静态出口 IP、代理配置、工作区目录（都不含身份）。外部 PDF 9.3 明确：
IP 没被拉黑就不用换。

## 销毁 vs 停止的语义区别

| 操作 | WSL | 容器 | 数据 |
| --- | --- | --- | --- |
| `stopAll()` | `wsl --terminate` | `docker stop -t 8` | 保留（日常停止） |
| `destroyAll()` | `wsl --unregister` + 清 vhdx | `docker rm -f` + 删 home 卷 | 全毁（重置专用） |
