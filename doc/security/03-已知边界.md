## 软件能保证的

| 需求 | 现状 |
| --- | --- |
| 出口只走代理、地区可验证 | netlink 锁 + 启动预检（地区 / 三源一致性 / 直连验证）；1.0.37 起可切 TUN ✅ |
| 配置漂了能自动恢复 | 3 秒 re-assert / 看门狗；TUN 模式下结构性 fail-closed ✅ |
| 指纹自洽 | hostname / locale / DNS 后缀 / Chrome policy / 字体 / 时区 ✅ |
| 状态看得见 | state 文件 + `exit-check.sh` 自检 ✅ |
| 封号后换全新环境 | 一键环境重置（销毁重建）✅ |
| **代理运行中切 Direct 时不假绿** | 旧链路 ❌（[直连盲点](../network/03-直连盲点.md)）；TUN 模式 ✅（架构上绕开） |

## 软件保证不了的（人工流程）

- 你买的 IP 干不干净（注册时是否弹手机号验证 / on hold）
- 三端是否同国（节点、静态 IP、指纹时区得自己选对）
- 账号行为是否触发风控（反代池、猛刷额度、逆向脱壳）

这几条 PDF 反复强调但代码管不着。详见[防封教程要点](../references/01-防封教程要点.md)。

## 两种显示模式的能力边界

见[显示模式](../desktop/02-显示模式.md)。共通点：音频不支持、文件拖拽不做（工作区目录双向可见代替）、
剪贴板在 desktop 模式只支持文本。

## 平台边界

- Windows 是主平台，WSL2 独立内核。
- macOS 容器后端**未在真机验收**，与 OrbStack/Docker 的 VM 共享内核；arm64 只覆盖内核二进制。
- Mac 上对隔离有硬要求建议直接用 Claude Cage，见[平台取舍](../decisions/04-平台与范围取舍.md)、
  [Claude Cage 对比](../references/02-Claude-Cage对比.md)。

## 威胁模型的收敛（重要）

本项目**防的是「平台被动风控」和「配置漂移 / 意外泄露」，不是「内部恶意进程」**。
Claude Code 不会主动探测出口 IP、不会 `ip route add`、没有绕过隔离的动机。
因此权限审计 / cap-drop / 双容器能力分离等「防内部提权」的工程**不采纳**。
详见[平台与范围取舍](../decisions/04-平台与范围取舍.md)。
