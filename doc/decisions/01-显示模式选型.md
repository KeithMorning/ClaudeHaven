# 决策：显示模式选型（WSLg 主路径，noVNC 兜底）

## 决策

1.0.21 起主路径改为 **WSLg 独立窗口**（`DISPLAY_MODE=wslg`，默认），
浏览器串流（noVNC）退为可选 / Mac 兜底（`DISPLAY_MODE=desktop`）。

```
Electron 应用（设置 / 自检 / 状态）
   └─ wsl -d claude-vm → entrypoint.sh
        ├─ DISPLAY_MODE=wslg    → 直接输出到 :0，Windows 上就是独立原生窗口
        └─ DISPLAY_MODE=desktop → Xvnc + noVNC:6080，<webview> 内嵌
```

## 理由

| 维度 | noVNC 串流 | WSLg |
| --- | --- | --- |
| 清晰度 | 桌面编码成图片再传，取决于带宽与 JPEG 质量 | 原生窗口，1:1 像素 |
| 剪贴板 | 文本轮询桥，图片/文件不通 | 系统原生双向 |
| 中文输入/快捷键 | 始终隔一层 | 真实 Windows 窗口，与本地一致 |

WSLg 是 WSL 自带的 Wayland/X 转发，体验接近本机。代价是要 Win11 或 Win10 19044+ 商店版 WSL。

## 适用条件

- 老 Win10（无 WSLg）、远程桌面场景、macOS（没有 WSLg）→ 用 desktop 模式。
- macOS 强制 desktop：mergeCfg 写死 `displayMode=desktop`，渲染层隐藏选项。

## 后续影响

- 双模式并存导致过两次回归：XIM 注册到 `:0` 而窗口在 `:1`（坑 14 根因 2）、
  desktop 分支缺 `sleep infinity &` 导致会话猝死（坑 14 根因 1）。
- 修复原则是「输入法整段放在 DISPLAY_MODE 分支之后」，别在 desktop 分支单独补一套 ——
  否则 wslg/desktop 两套逻辑越漂越远。
- 输入法的零候选问题（坑 20）实测两模式一致，因为根因在 fcitx5 classicui 的窗口映射，
  与 X server 类型无关。
