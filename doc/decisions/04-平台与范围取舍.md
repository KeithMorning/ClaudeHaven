# 决策：平台与范围取舍

> 记录几条「做不做、做到什么程度」的判断。共同主线：**目标窄（只用来编码的 Windows 环境），
> 没必要照搬更宽盘子产品的复杂度**。

## Mac 后端：容器可行但不投

做过的调研：1.0.32 加了 Docker/OrbStack 容器后端，1.0.33 修了 `getBackend()` 接线与
XDG_RUNTIME_DIR，但**未在真机验收**。后续判断：

- 容器后端在 Mac 上更站不住：要用户额外装 Docker/OrbStack + 开 Rosetta，
  隔离还更弱（与 OrbStack 那台 VM 共享内核），正好是 Claude Cage 最强、我们最弱的地方。
- OrbStack 的 Linux machine **也共享内核**（官方原话 "not independent VMs"），
  换 machine 类型拿不到独立 VM。
- **决定**：容器后端保留但标实验性，不再当正式能力宣传；Mac 上对隔离有硬要求建议直接用 Cage。

## arm64 rootfs：是体验优化，不是安全补齐

用户提出把 rootfs 打成 arm64 省 Rosetta 翻译。调研结论：

- 三个硬依赖都有 arm64 版（Node linux-arm64、Chrome arm64.deb、
  `@anthropic-ai/claude-code-linux-arm64`），apt 包 Ubuntu 22.04 arm64 也齐。
- 但 apt 源路径要按 `TARGETARCH` 分支（arm64 走 `/ubuntu-ports/`）、
  Node 要升 22（最新 Claude Code 要求 >=22）、打包不能让 Mac 包翻倍。
- **arm64 只解决性能**：还是容器、还是共享内核、还是 net-guard 删路由，安全边界一条没动。
- 1.0.37 的 Dockerfile 只把**内核二进制**做了 TARGETARCH 双架构，apt/Node/Chrome/PATH 仍 amd64 写死。
- Cage 的 macOS DMG 其实只有 207 MB，大件在客机镜像；我们 arm64 rootfs 620 MB 直接进包，
  下载量上并不占优，优势只是「下完就能用 + 完整桌面和输入法」。

## 指纹浏览器：不换，流程分工

对照防封 PDF 细读后发现：那篇文章名为「指纹浏览器教程」，核心动作恰恰是**把伪造功能全关掉**
（Canvas/WebGL/audio 假噪音全关、元数据选真实、随机指纹关闭）——AdsPower 只是「环境隔离 +
出口绑定的壳子」。而我们的 VM 做的是同一套、层级更低更彻底（内核层 fail-closed vs 应用层）。

更关键：**主战场是 Claude Code 终端，浏览器只负责登录授权**。PDF 第七章明确 Claude Code
不读主板序列号/MAC，服务端关联「账号 ID + 本地随机设备 ID + 会话 ID」——
指纹浏览器优化的那套对 Claude Code 请求几乎不起作用。

**决定**：不换浏览器。注册/首次授权用 AdsPower 建干净窗口，注册完把号拿进 ClaudeVM 日常编码。
可选补项：时区跟随出口 IP 做成「提示 + 一键应用」（不静默自动）、端口扫描保护。

## 权限审计 / cap-drop / 双容器：不采纳

曾论证「业务以 root 跑，理论上能自己 `ip route add` 拆锁」。技术上没错，但**在防一个不存在的对手**：
Claude Code 不会主动探测出口、不会拆 net-guard 的锁。真正让状态漂移的是配置意外
（Clash 切 Direct、WSL 网络重置加回默认路由、DNS 走宿主、IPv6 漏出）——这些是误操作，不是攻击。

**威胁模型收敛**：防平台被动风控 + 配置漂移，不防内部恶意进程。
权限审计要有强制力必须配套降权，而降权会重踩 XDG_RUNTIME_DIR / D-Bus / fcitx5 那串坑
（1.0.33/34/36 都这么来的），维护面翻倍而收益为零。

## 与 Claude Cage 的关系

Cage 是同赛道更成熟的方案（Go 重写、三平台、主机侧强制 + 90 秒租约 + 内置 Mihomo），
但**没有完整桌面**，绕开了我们硬啃的中文输入法。定位差异见
[Claude Cage 对比](../references/02-Claude-Cage对比.md)。

我们的护城河只剩「Windows 上带完整桌面 + 可用中文输入的编码环境」。
最小充分集 = 现有 1.0.37（网络防漏 + 指纹自洽 + 一键重置），不再叠一整套安全架构。
