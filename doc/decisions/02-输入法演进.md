# 决策：输入法演进（IBus → lxterminal → fcitx5）

> 一条被反复推翻又重建的路径。核心结论：**「壳」的问题不要用「引擎」的复杂度去修**。
> 七条坑的完整实录见[坑档案 03](../pitfalls/03-输入法.md)。

## 演进时间线

| 版本 | 方案 | 为什么变 |
| --- | --- | --- |
| 1.0.23~1.0.25 | IBus + Rime + XIM，xterm | WSLg 不转发 preedit，把输入法搬进 VM；fcitx5 5.0 移除 XIM 走不通 |
| 1.0.26 | 万象 Pure 词库替换台湾注音 | 注音是大千键盘，拼音用户打不了字；对检测评分零影响 |
| 1.0.31 | lxterminal + ibus-gtk3 | 终端一个中文打不进（缺 `im-ibus.so`）；先量体积，lxterminal 最小 |
| 1.0.33 | 修 XDG_RUNTIME_DIR | 属主 uid 1000 与 root 不匹配 → GTK3 卡死，窗口永不出现 |
| 1.0.34 | **换 fcitx5** | IBus 候选面板在 VNC 里到天花板（钉左下角、竖排、豆腐块） |
| 1.0.35 | 补 HanaMin 字体 | CJK 扩展 B 区生僻字方框 |
| 1.0.36 | 关 client preedit | `ffff` 零时候选窗消失、退格全盲 |

## 关键决策点

### 为什么曾经不用 fcitx5（1.0.26）

fcitx5 5.0 起**移除 XIM**（只剩 DBus/GTK/Wayland），而当时 xterm 只认 XIM。
实测 `fcitx4frontend` 补了 dbus 能加载，但 `xprop -root XIM_SERVERS` 始终 no such atom。
所以走 IBus + `ibus-daemon -d --xim`。

### 为什么最终又换 fcitx5（1.0.34）

到 1.0.33，引擎链路（im-ibus + Rime + 万象）已经全线打通（nihao→你好 实测通过），
剩下的全是**壳**的问题：IBus 候选面板自己钉在左下角、竖排旧样式、字体回退差。
1.0.26~1.0.33 七轮修补无进展 → 换 fcitx5。

**词库全复用**：从 `~/.config/ibus/rime` 迁到 `~/.local/share/fcitx5/rime`，
排除 `build/` 跨引擎重编，避免 146 MB 重新解压。
主链路本来就是 GTK3 im module（lxterminal/Chrome），fcitx5 没有 XIM 也无所谓。

### 三个陷阱（换壳引入）

1. guard 在 D-Bus 导出前启动 → fcitx5-remote 探活失败 → 每 4 秒杀掉重拉。
2. 进程活着 ≠ 可输入：默认 state=1（透传 ASCII），要 `-s rime` 才到 state=2。
3. Ctrl+Space 跨实验粘滞，测试互踩。

### 体积优先的选型方法

1.0.31 先量了包体积：`ibus-gtk3` 80KB、`lxterminal` 593KB、`sakura` 272KB、
`xfce4-terminal` 2448KB + 8 个库。选 lxterminal：最小 + 项目已有同色配置。
用户明确要求「按 A 改，优先体积小、体验好」。

## 教训沉淀

- 协议层死结（preedit 不转发）别靠加参数硬凑（`openIm` / `preeditType` 都试过）。
- `GTK_IM_MODULE` 设了 ≠ 模块装了（`im-ibus.so` 缺失的教训）。
- 服务「起来」和「可用」之间隔着激活语义（fcitx5 state）。
- 自动化有边界：xdotool 合成键不触发 IME 组合，最后一步必须真人验证。
- 字体按码位判定覆盖（`fc-list ':charset=20000'`），与具体包解耦。
