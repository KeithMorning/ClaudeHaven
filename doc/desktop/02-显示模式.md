# 显示模式：wslg 与 desktop

> `DISPLAY_MODE=wslg`（默认，推荐）把窗口直接输出到 `:0`，是 Windows 真实窗口；
> `DISPLAY_MODE=desktop`（noVNC 串流，可选 / Mac 兜底）走 Xvnc + websockify，在 `<webview>` 内嵌。

## wslg 模式（默认，推荐）

| 项 | 状态 |
| --- | --- |
| 清晰度 | 原生窗口，1:1 像素，无编码无压缩 |
| 剪贴板 | **系统原生双向**（文本/图片都行），不依赖任何轮询桥 |
| 快捷键 | 真实 Windows 窗口，Ctrl+C/V、Ctrl+Shift+T 等与本地一致 |
| 中文输入 | 默认「宿主输入 → 粘贴」；装 fcitx5 万象后可在 VM 内直接打中文，见[输入法](01-输入法.md) |
| 音频 | 不支持 |
| 文件拖拽 | 不做，工作区目录双向可见代替 |

## desktop 模式（noVNC，可选 / Mac 兜底）

| 项 | 状态 |
| --- | --- |
| 清晰度 | `resizeSession=true` + `qualityLevel=9`，分辨率跟随窗口，仍受 JPEG 编码限制 |
| 剪贴板 | 文本双向通（250 ms 轮询），图片/文件传不了（RFB 协议限制） |
| 快捷键 | 菜单已移除，Ctrl+W / Ctrl+R 等透传 |
| 中文输入 | 同样是「宿主输入 → 粘贴」；VM 内输入法见[输入法](01-输入法.md) |
| 音频 / 拖拽 | 同 wslg |

## WSLg 的 IME 边界是协议层的

WSLg 只转发按键 / 已提交的文本，**不转发 Windows IME 的 preedit 组合串**，不是配置问题。
两条路：
1. 把输入法整体搬进 VM（fcitx5 + Rime，当前方案），组合在 Linux 侧完成；
2. 宿主侧输入法小工具（Windows 选词 → 写剪贴板 → 目标窗口 Ctrl+Shift+V）。

## 桌面稳定性与常见故障

串流桌面曾出现「意外退出 + Chrome 打不开 + 输入法切不了」三连 —— 实为**同一次会话猝死**的衍生状态：
entrypoint 开头 `set -e`、末尾 `wait`，desktop 分支缺 `sleep infinity &`，任一组件退出就整段结束。
修法是 desktop 也放兜底 + `desktop-guard.sh` 每 4 秒自愈组件。完整复盘见
[坑 14](../pitfalls/04-桌面与Electron.md)。

其他桌面坑：Openbox 按钮 context 官方命名（坑 12）、假活判定与幂等跳过同步（坑 13）、
`<webview>` 图层遮挡与 preload sandbox（坑 5/6）、WSLg 窗口存活依赖 `wsl.exe`（坑 7）——
都在[pitfalls/04-桌面与Electron.md](../pitfalls/04-桌面与Electron.md)。
