# 网络与安全检查审计

本审计记录改造前 Tauri「网络与安全」页面调用的旧检查。下表描述旧检查的证据和局限；新流程见文末。结论基于代码和隔离模拟测试，不代表对当前网络的完整泄漏测试。

| 项目 | 实际依据 | 可以说明什么 / 局限 |
| --- | --- | --- |
| 内核、TUN 网卡 | `pgrep mihomo`、`/proc/net/dev` | 进程和网卡是否存在；不证明所有连接都走代理。 |
| DNS 归属 | `resolv.conf` 首个服务器、`getent` 的 fake-IP | 系统解析器的配置与一次解析结果；不是浏览器 DNS 泄漏测试。 |
| 节点名称 | 启动时保存的环境变量 | 配置信息，不是网络实测，也不能证明当前出口。 |
| 多源出口一致性 | 访问三个公共 IP 查询服务并比较合法 IP | 这些服务的本次响应是否一致；不能证明所有域名、协议都一致。 |
| 出口可达性 | curl 请求一个查询服务 | 此次请求是否取得响应；不能证明是否绕过 TUN。 |
| Anthropic 接口响应 | 请求 `api.anthropic.com`，记录 HTTP 状态 | 是否收到响应；403、500 等不意味着账号或 API 可正常使用。 |
| claude.ai 人机校验 | curl HEAD 响应状态和 `cf-mitigated` 标头 | 本次命令行请求的结果；不能等同于实际浏览器登录结果。 |
| DNS 搜索域 | `resolv.conf` 中的 search/domain | 是否存在搜索域，不证明 DNS 无泄漏。 |
| 网络守卫状态 | 守卫状态文件 | 守卫记录的状态，须结合进程、心跳和路由；不是独立的断网实测。 |
| 直连封锁验证 | 查询 IPv4 主表默认路由和 IPv6 开关 | 这两个本地状态；没有模拟代理崩溃，也没有覆盖所有路由、协议和例外。 |
| 代理预检 | 守卫状态文件中的预检结果 | 上一次守卫预检的结果，可能不是当前每条连接的结果。 |
| 守卫心跳 | PID、进程命令行及状态时间戳 | 守卫进程和状态是否看起来存活、近期更新；不证明实际链路无泄漏。 |
| 出口 IP、地区、组织 | ipinfo 的单次响应 | 第三方给出的出口信息，可能过时或不准确，组织名称不能证明 IP 类型。 |
| 时区与出口地区 | 启动配置和第三方地理信息 | 信息展示，不作账号风险判断。 |
| 出口规则 | 检查生成配置包含 `MATCH,ClaudeVM` | 配置中存在相应字符串；不证明实际加载的规则与所有流量路径。 |

已移除 Tauri 页面中的节点延迟项：它读取先前测速结果，而当前 Tauri 界面没有触发测速的入口。已移除通过 CheckCC 非公开字段及本地假设推算的分数，旧检查脚本保留兼容字段并以 `null` 表示不可用。

## 隐私与范围

启动守卫和网络检查会向 ipinfo.io、api.ipify.org、api.ip.sb、api.anthropic.com 和 claude.ai 等服务发送请求，服务端能看到请求的出口 IP 及其通常可见的网络元数据；守卫周期探活还会请求 Cloudflare。新检查不再向 CheckCC 发送自动评分请求。检查不是在实际浏览器中完成，不包括 WebRTC 公网地址、浏览器 DNS 或代理失效后的真实流量测试。

## 必须继续处理的保护问题

1. 守卫把 mihomo 进程和 Meta 网卡存在当作 TUN 接管的前提，而不是独立验证实际路由；先前命名为直连泄漏的测试结果还会被覆盖，不能据此宣称已实测不存在泄漏。
2. 新守卫只使用一个出口地区服务，无法消除该服务不可用、地理信息错误或不同目标走不同出口的可能。地区未知时现在会阻止启动，不能将其当成通过。
3. 新的启动预检会独立核对 IPv6 开关与主表路由，但还需要在隔离环境中实测节点中断、路由变化和 IPv6 旁路，不能只凭状态文件证明不泄漏。
4. 为连接节点和 DNS，上游地址及部分本地网段配置了路由例外。因此“所有流量都走代理”“绝不会泄漏”都不是当前检查能够证明的结论。需要隔离环境下验证代理退出、路由重置、DNS、IPv6、UDP 和浏览器 WebRTC 等场景。
5. 旧版完整环境检查仍包含字体、浏览器语言、地区等推断，部分文案将 Node 或 Chrome 配置当作真实浏览器行为。Tauri 的网络检查已不再运行这些项目，但旧版报告仍需单独整改。

CheckCC 是第三方项目，不是 Anthropic 官方判断；其项目说明也明确提醒不要将结果作为账号安全或订阅状态的唯一依据。https://github.com/yacuo/check-cc

## 当前 Tauri 流程

- 启动守卫先检查本地代理进程、TUN、主表默认路由、IPv6 和 DNS 配置，再查询一次出口 IP 的地区，并对照 2026-11-18 查阅的 Anthropic 官方政策快照。无法确认时不标记为通过。快照在 `claude-supported-regions.py`，需持续维护；乌克兰因官方列有地区例外而仅凭国家码无法确认。地区查询不能判断人的实际所在地或账号资格。
- “网络与安全”页面只展示网络保护和出口地区两项。此前试验的独立 Claude 环境自检和浏览器检查页已移除。
- 系统 DNS 由应用覆盖 YAML 的 DNS 部分并设定为 `223.5.5.5` 和 `1.1.1.1`，节点地址及这些 DNS 服务器被加到路由例外中；Chrome 还配置了 Cloudflare DoH。DNS 请求究竟会如何经过这些路径，仍需针对当前 WSL 和内核版本独立实测。
